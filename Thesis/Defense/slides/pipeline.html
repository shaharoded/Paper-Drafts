A shared front end, two branches

About 1.5 minutes. Walk the figure left to right. 1. Preprocessing. Both datasets go through ETL into a common event stream, a static context vector, and one concept vocabulary. MIMIC-IV is mapped to standard vocabularies. Kineret had no mapping to an international coding system at the time, so a dataset-specific concept index was built by hand, mapping about 1,500 local codes onto roughly 70 knowledge-base concepts. Once the index exists, the same knowledge base and engine run unchanged on either source. 2. The Mediator (our reimplementation of the Temporal Mediator) executes the knowledge base against each record and returns the interval set, and in the same pass scores the guideline patterns. 3. Two branches over the same intervals: temporal pattern mining (KarmaLego, TIRPs, TPF vectors) for the symbolic baseline, and tokenization for the transformer. 4. Prediction and evaluation, then QATP and feature-importance analysis, which feeds back into the knowledge base (the "adjusting protocol" loop). Deployment constraint worth mentioning: Kineret lives on a secure Ministry of Health cloud platform, so the Mediator, mining pipeline and models all had to run inside Linux containers in a resource-constrained remote environment.
